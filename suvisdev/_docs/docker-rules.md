# Docker 컨테이너 생성 규칙

> **용도:** `docker run` / `docker compose up` 등으로 컨테이너(특히 DB·backend)를 새로 만들기 전에 참조한다.
> 워크스페이스 전체 규칙은 루트 `CLAUDE.md`를 함께 본다.

---

## 핵심 원칙

**DB·backend처럼 이미 존재할 수 있는 서비스를 만들라는 지시를 받아도, 먼저 기존 컨테이너가 있는지 확인하고 있으면 사용자 승인 없이 새로 만들지 않는다.**

- 만들기 전에 `docker ps -a`로 동일 역할(같은 이미지 계열·포트·서비스명)의 컨테이너가 이미 있는지 확인한다.
- 있으면 (실행 중이든 꺼져 있든) 임의로 새 컨테이너/이미지를 또 만들지 않는다. 대신:
  - 기존 컨테이너를 재사용·재시작하는 방법을 먼저 제안하거나,
  - 그래도 새로 만들어야 한다면 이유를 설명하고 **사용자 승인**을 받은 뒤 진행한다.
- 이 판단은 현재 작업 디렉터리의 `docker-compose.yaml` 기준으로 한다 — 다른 경로에서 만들어진 동명 프로젝트(`docker compose -p` 등)가 있을 수 있으니 컨테이너 라벨의 `com.docker.compose.project.working_dir`도 확인한다.

## 배경

2026-07-16, `/home/ssu/suvisdev.cloud`라는 다른 경로에서 예전에 만든 `suvisdevcloud-backend-1`/`suvisdevcloud-frontend-1` 컨테이너(한 번도 시작 안 됨)와 13.5GB짜리 고아 이미지가 방치돼 있었던 사례가 있음. 원본 디렉터리는 이미 삭제된 상태였음. 확인 없이 중복 생성이 쌓이면 이렇게 디스크만 차지하는 고아 리소스가 남는다.
