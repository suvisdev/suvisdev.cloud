# 자동 메모리 동작 방식

Claude Code의 자동 메모리가 **무엇을 언제 읽는지**에 대한 메모. 메모리를 어디에
쓸지 정할 때 참고한다.

> 아래는 전부 **홈**(`~/.claude/projects/<프로젝트 경로>/memory/`) 기준이다.
> 지금 이 파일이 있는 저장소 쪽 디렉터리는 자동 로드 대상이 아니다 — 두 위치의
> 차이는 [MEMORY.md](MEMORY.md) 상단 참고.

## 무엇이 자동으로 로드되나

| 대상 | 로드 시점 | 범위 |
|------|-----------|------|
| `MEMORY.md` | 매 세션 시작 | **첫 200줄만** |
| `MEMORY.md` 200줄 초과분 | 자동 로드 안 됨 | 필요할 때 읽음 |
| `debugging.md`·`patterns.md` 등 주제 파일 | 자동 로드 안 됨 | 필요할 때만 읽음 |

- **200줄 제한은 `MEMORY.md`에만 적용된다.** 주제 파일에는 길이 제한이 없다.
- 그래서 `MEMORY.md`는 **인덱스**로 유지하고, 실제 내용은 주제 파일로 분리한다.
  인덱스가 200줄을 넘기면 넘긴 부분은 세션 시작 시 보이지 않는다.

## `CLAUDE.md`는 다르다

- `CLAUDE.md`는 **길이와 무관하게 전체가 로드된다.** 200줄 제한은 자동 메모리
  전용 설정이라 여기엔 적용되지 않는다.
- 다만 **200줄 이내로 유지하는 편이 지시사항 준수율에 유리하다.** 길어지면 개별
  지시가 묻힌다.
- 참고: 이 저장소의 루트 `CLAUDE.md`는 2026-07-29 기준 **216줄로 권장치를 넘겼다.**
  더 늘릴 내용은 `.claude/rules/`(경로 한정)나 `_docs/`로 빼는 것을 먼저 검토한다.

## 활성화 / 비활성화

기본값은 **활성화**다(이 저장소·홈 설정 어디에도 `autoMemoryEnabled`가 없으므로
현재 기본값으로 동작 중).

끄는 방법은 두 가지다.

```bash
# 1) 환경변수
export CLAUDE_CODE_DISABLE_AUTO_MEMORY=1
```

```jsonc
// 2) settings.json
{
  "autoMemoryEnabled": false
}
```

- 다시 켜려면 환경변수를 지우거나 `autoMemoryEnabled`를 `true`로 둔다.
- `/memory` 명령어의 토글로도 켜고 끌 수 있다.

## 실무 지침

- `MEMORY.md`에는 **한 줄 요약 + 링크**만. 본문을 넣지 않는다.
- 새 주제가 생기면 주제 파일을 만들고 `MEMORY.md` 인덱스에 한 줄 추가한다.
- 주제 파일은 자동으로 안 읽히므로, 세션에서 쓰려면 **읽으라고 지시**해야 한다.
