근거: 바탕화면 밖 `Documents/fde/game_ops/CS_INTEGRATION_GUIDE.md`(이하 가이드), 참고 구현 `fde/game_ops/`.
상태: **사용자 승인 대기**(11-25 작성). 사용자 결정(11-25): LLM은 Claude Code 헤드리스(`claude -p`, 추가 비용 없음) · 판 기록 저장부터 포함 · 신고 유형은 제안대로.
**LLM 결과는 참고용. 제재는 운영자가 한다. 데이터를 바꾸는 도구는 만들지 않는다.**

## 2. 구조

```
[앱] 고객센터 화면: 유형·상대 닉네임(선택)·발생 시각·내용  ──POST /api/cs/reports──▶ [서버] reports 저장(접수)
[노트북 워커] kumoniji/cs/worker.py (systemd 유저 서비스)
   접수 건을 가져와 ① 분류 ② 추출 ③ 조회·채점(읽기 전용 도구) ④ 자기 검증 → 결과 저장(분석 완료/실패)
[앱·웹] 운영자 화면(/cs/review): 우선순위 순 목록·상세(참고용 표시, 조회 기록 펼치기), 보충 메모 → 재분석
```

- 왜 워커가 노트북 호스트에서 도나: `claude -p`는 노트북에 로그인된 Claude Code라 파드 안에서 못 부른다. 운영도 노트북 한 대라 같은 기계(ADR-0008).
- 워커의 조회 연결은 **SELECT만 되는 DB 계정**(`kumoniji_cs_ro`), 결과 저장은 reports 표만 쓰는 별도 계정.
- 노트북이 꺼지면 분석이 멈추고 접수는 쌓인다(다시 켜지면 이어서).

## 3. Rubric(채점 정책, 첫 판 — dev 오답을 보고 고친다)

| 유형 | 조회 | supported | contradicted | unverifiable |
|---|---|---|---|---|
| 잠수·고의 지연 | 판 기록(마감 자동 패스·끊김) | 대상이 그 판에서 마감 자동 패스·끊김이 반복(기준은 dev에서 정함) | 대상이 매번 제때 냄 | 그 시각·닉네임으로 판을 못 찾음 |
| 불건전 닉네임 | 닉네임 | 대상 닉네임이 있고 글이 말한 단어를 담음 | 그런 닉네임이 없음/단어 없음 | — |
| 봇·매크로 의심 | 판 기록(수 간격) | 수 간격이 비정상적으로 일정·빠름이 여러 판 | 사람 수준의 간격 | 기록 부족 |
| 버그 악용 | 판 기록·원장 | 규칙상 불가능한 결과·원장 이상 | 정상 | 기록 없음 |
| 재화 문제 | 원장(신고자 본인) | 원장에 말한 증감이 없음/이중 차감 | 원장이 정상 | 시각 범위에 기록 없음 |
| 기타 | — | — | — | 기본 unverifiable |

## 4. 작업(각 단계 끝에 완료 기준)

1. **판 기록 저장**(마이그레이션 004 `match_log`: 판 id·시작·자리별 계정/닉네임·수 목록(시각·자리·패/패스/자동 패스)·끊김/재접속·정산). 멀티 판이 끝날 때 한 번 저장(판 끝 기록과 같은 재시도). 완료: 멀티 판 1개를 끝까지 치면 행 1개, 수 개수 일치.
2. **reports 표·API**(마이그레이션 005): `POST /api/cs/reports`(로그인 필요, 하루 개수 제한), 운영자용 `GET /api/cs/reports`·`/{id}`·`POST /{id}/supplement`. 운영자 = `accounts.admin`(사용자 계정만 SQL로 켬). 보충 메모·분석 겹침 규칙은 가이드 4-8.
3. **`cs/llm_call.py`**: 참고 구현 `claude_headless.py`를 옮김(Haiku 5.5, 시스템 프롬프트만, 도구 없음, temperature 없음, refusal 재시도 없음). 완료: 스키마 호출 1번·도구 호출 1번 성공, 비용(추정)·시간 기록.
4. **조회 도구**(읽기 전용 연결, SQL 고정·바인딩): `search_matches(nickname, date)`, `get_match(id)`, `get_nickname(nickname)`, `get_ledger(account, from, to)`(신고자 본인만), `get_report_history(nickname)`, `submit_review`. 없는 기록은 `{"found": false}`. 완료: 도구마다 있는/없는 기록 직접 호출, 쓰기 SQL 거부 확인.
5. **분류·추출·채점·자기 검증·파이프라인**(가이드 4-3~4-7). 신고 글은 데이터(지시 무시).
6. **워커**: 접수 건을 하나씩, 실패는 '분석 실패'로. systemd 유저 서비스(`kumoniji-cs.service`).
7. **화면**: 앱 홈 '고객센터'(접수, 내 신고 상태), 운영자 화면(우선순위 정렬, 유형 다름·분석 실패 배지, 참고용 표시). 내부 번호 입력칸 없음.
8. **평가**: 가짜 DB + 가짜 신고를 코드로(문항마다 시드), dev 100 + test 200, 함정(유형 틀림·상대 날짜·닉네임 모름·기록 반대·기록 없음·여러 유형·지시문 섞임). 지표·이어 하기·summary.csv는 가이드 5장. v1 베이스라인 → 기법 하나씩 → 제거 실험 → test 1회.
