# 쿠모니지 멀티 — 자동 매칭·친구방 (계획 C)

**Goal:** 로그인한 사람 4명이 자동 매칭 또는 친구방 코드로 모여 실시간으로 한 판을 친다. 차례마다 20초, 넘기면 자동 패스.

**Architecture:** 판정·진행은 지금 `Game`을 그대로 쓴다(서버 권위). 멀티 판·대기열·방은 **메모리**에 두고 replicas 1을 유지한다(기획 결정 T 초안 "서버가 판 도중 멈추면 그 판은 무효"와 맞음). 실시간 전달은 FastAPI WebSocket 하나(`/api/ws`). 각 판은 asyncio 작업 하나가 차례 타이머를 돌린다. 사람마다 자기 손패만 담은 상태를 보낸다(남의 패 비공개).

**Tech Stack:** FastAPI WebSocket(starlette) · asyncio / Flutter `web_socket_channel`

## Global Constraints
- 계획 A(선도 패스 가능)·계획 B(로그인)가 먼저 머지돼 있어야 한다. 인증된(`verified_at`)·MFA 통과 세션만 입장.
- 11-21 사용자 결정: **자동 매칭과 친구방 둘 다**(지인과도 칠 수 있게), **4명이 찰 때까지 대기**(봇으로 채우지 않음), **20초 넘기면 자동 패스**(선이어도 — 계획 A 규칙).
- 기획(README 11-17): 판마다 새로 매칭, 같은 사람과 이어서 치지 않음, **같은 IP·기기는 자동 매칭에서 같은 판에 안 넣음**. 친구방은 지인용이라 이 제한을 걸지 않는다(한 집에서 같이 칠 수 있게).
- 범위 밖: 하트·판돈·정산 기록 저장·순위(재화 단계). 판 결과는 화면에만.
- WebSocket(SECURITY 29): 연결 때 Origin·인증 검사, 메시지마다 "그 판의 그 자리 주인인가" 검사, 메시지 크기 2KB·초당 10개·계정당 연결 1개·유휴 60초(핑) 제한, 세션 폐기·탈퇴 시 연결 종료, URL에 토큰 없음(웹은 쿠키, 앱은 연결 직후 첫 메시지로 액세스 토큰).

## 파일 구조

```text
kumoniji/server/kumoniji/
├── multi/
│   ├── table.py      # MultiTable: Game + 자리별 계정·연결 + 20초 타이머(asyncio) + 자리별 상태 만들기
│   ├── lobby.py      # 자동 매칭 대기열(IP·기기 분리) + 친구방(6자리 코드, 방장, 4명 차면 시작)
│   └── ws.py         # /api/ws: 인증·Origin·제한, 메시지 → lobby/table, 끊김 처리
├── api.py            # 상태 직렬화(view)를 자리 번호 받는 함수로 일반화해 싱글·멀티가 같이 씀
└── tests/multi/      # 가짜 시계로 타이머, TestClient 웹소켓 4개로 한 판 끝까지
kumoniji/app/lib/
├── multi/lobby_screen.dart   # 자동 매칭 대기 / 친구방 만들기·코드 입력·대기실
├── multi/socket.dart         # 연결·재연결·메시지
└── table_screen.dart         # 싱글/멀티 공용으로: 자리 회전(내가 항상 아래), 남은 시간 표시
```

## 프로토콜 (JSON, 한 줄)

```text
클라 → 서버
{"t":"auth","token":"..."}                 # 앱만, 연결 직후 5초 안에
{"t":"queue"} / {"t":"unqueue"}            # 자동 매칭
{"t":"room.create"} / {"t":"room.join","code":"K7Q2MX"} / {"t":"room.leave"} / {"t":"room.start"}  # 방장만 start, 4명일 때만
{"t":"move","game":"<id>","tiles":["s3","s4"]}   # [] = 패스
{"t":"ping"}

서버 → 클라
{"t":"queued","waiting":2} / {"t":"room","code":"K7Q2MX","members":[{"nick":"..","host":true},..]}
{"t":"state", ...싱글 view와 같은 모양 + "seat":내 자리, "names":[4], "deadline":에포크 초, "connected":[4]}
{"t":"error","code":"not_your_turn"|"illegal"|"room_full"|"no_room"|...}
```
- `state.events`는 싱글처럼 직전 상태 이후의 수 목록 → 앱의 기존 장면 재생 코드를 그대로 쓴다.

## 태스크

### Task 1: 자리별 상태 직렬화 일반화
- `api.view(g, seat)`로 바꿔 손패·낼 수 있는 조합을 그 자리 기준으로, 남의 손패는 장수만. 싱글은 `view(g, 0)`.
- 테스트: 자리 2의 view에 다른 자리 타일 코드가 없음(문자열 검색), 싱글 API 응답은 바뀌지 않음(기존 테스트 통과).

### Task 2: MultiTable과 20초 타이머
- `MultiTable(game, accounts[4], clock)`: `move(account, tiles)` → 자리·차례 검사 후 `game.play`, 다음 차례 마감 = now+20. 타이머 작업이 마감에 `game.play(turn, None)`(자동 패스 — 계획 A로 선도 가능). 수가 들어오면 타이머 재설정. 잠금은 판별 `asyncio.Lock`.
- 끊긴 사람도 같은 규칙(차례마다 20초 뒤 자동 패스). 다시 연결하면 그 자리 상태를 바로 받고 이어서 침.
- 네 명 모두 끊긴 채 3분 → 판 종료(무효)·메모리에서 제거.
- 판이 끝나면 결과 상태를 보내고 10분 뒤 제거.
- 테스트(가짜 시계): 20초 지나면 패스 이벤트·차례 이동, 19초엔 그대로, 수가 들어오면 마감 재설정, 남의 차례에 낸 수 거부, 4명 끊김 3분 뒤 제거, 결과까지 무작위 진행 200판(모두 자동 패스·무작위 합법 수)에서 예외 없음.

### Task 3: 자동 매칭 대기열
- `lobby.queue(account, ip, device)`: 대기열 앞에서부터 IP·기기가 겹치지 않는 4명을 고르면 판 생성. 이미 다른 판·방·대기열에 있으면 거부. 연결이 끊기면 대기열에서 뺌.
- 판마다 새로 매칭: 판이 끝나면 다시 `queue`를 눌러야 함(같은 4명이 자동으로 이어지지 않음).
- 테스트: 4명 들어오면 판 생성·각자 자리 배정, 같은 IP 두 명은 같은 판에 안 들어가고 다음 사람을 기다림, 대기 중 끊기면 빠짐, 중복 입장 거부.

### Task 4: 친구방
- `room.create` → 6자리 코드(헷갈리는 글자 0/O/1/I 제외, `secrets`), 만든 사람이 방장. `join`은 4명까지, `start`는 방장·4명일 때만 → 자리 무작위 섞어 판 생성. 방장이 나가면 다음 사람이 방장. 빈 방은 즉시 제거, 30분 지난 대기 방 제거.
- 코드 대입 방지: 계정당 `join` 실패 분당 10회 제한.
- 테스트: 만들기·참여·5번째 거부·방장 아닌 start 거부·3명 start 거부·방장 이탈 승계·잘못된 코드 연속 실패 제한.

### Task 5: WebSocket 엔드포인트
- `/api/ws`: Origin == 공개 원점(앱은 Origin 없음 → 첫 메시지 `auth` 필수), 쿠키 또는 첫 메시지 토큰을 계획 B의 `current_user`와 같은 검사(세션·auth_version·verified·MFA). 계정당 연결 1개(새 연결이 오면 옛 연결 종료). 2KB·초당 10개·유휴 60초 제한. 세션 폐기를 알 수 있게 60초마다 세션 재확인 → 폐기면 닫음.
- 테스트: 다른 Origin 거부, 토큰 없음·폐기 세션·미인증 계정 거부, 큰 메시지·폭주 시 종료, 로그아웃 뒤 60초 안에 종료, TestClient 웹소켓 4개로 자동 매칭 → 한 판 끝까지(모두 서버 `moves` 중 첫 번째를 냄).

### Task 6: 앱 — 로비·멀티 판
- 메인 "멀티" 버튼 활성화(로그인 필요 → 계획 B 화면). 로비: [자동 매칭] [친구방 만들기] [코드로 참여]. 대기 화면에 "n/4명", 취소.
- `TableScreen`을 싱글/멀티 공용으로: 데이터 출처만 다름(HTTP 응답 vs 소켓 `state`). 내 자리가 항상 아래가 되게 자리 회전. 차례인 사람 이름 옆에 남은 초(마감 기준 카운트다운), 끊긴 사람 표시.
- 소켓 끊김 → 1·2·4·8초 재연결, 붙으면 서버가 현재 상태를 보냄.
- 위젯 테스트(가짜 소켓): 대기 → state 받으면 판 화면, 내 자리가 아래, 남은 시간 줄어듦, 남의 차례엔 내기 버튼 꺼짐, 끊겼다 붙으면 같은 판.
- 로컬 4창 Playwright로 친구방 한 판 화면 캡처.

### Task 7: 배포·문서
- `k8s.yaml`: Ingress가 WebSocket을 그대로 통과하는지(Traefik은 기본 지원, Cloudflare 터널도 지원) 운영에서 실측. 배포 중 판은 사라짐 → 배포 전 진행 중 판 수를 로그로 확인하는 명령을 `kumoniji/CLAUDE.md`에.
- 워크로그·ADR(메모리 보관·replicas 1·봇 미충원·친구방 IP 제한 제외)·면접 질문.
