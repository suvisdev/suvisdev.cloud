# ADR-0028: 쿠모니지 상점은 화면부터, 현금 결제는 게임위 문의 뒤

상태: 확정 (2026-11-27, 사용자 결정)

## 문제

결제를 붙이려면 상점이 있어야 한다(사용자). 그런데 쿠모니지는 골드를 판돈으로 다른 사람과 주고받는 구조라, 현금으로 골드를 팔면 웹보드게임(맞고·포커류) 규제 — 월 구매 한도, 이체 금지 등 — 를 받을 가능성이 크다. 현금 판매 자체가 허용되는지는 확인하지 못했다.

## 결정

- 상점 탭 셋: 무지개 조각(현금 묶음, '준비 중' — 값만 보이고 못 삼) · 골드 · 햇살. 골드·햇살은 지금처럼 무지개 조각으로 산다.
- 묶음은 보통 게임 상점처럼 클수록 덤: 무지개 조각 ₩1,200→12 … ₩119,000→1,488(+25%), 골드 조각 10→1,000 … 300→40,000(+33%), 햇살 10→5·25→15(+20%). 숫자는 서버 `wallet/money.py`(골드·햇살)와 앱 `wallet.dart`(무지개 조각 묶음) 한 곳씩.
- 실제 결제(Google Play 결제)는 게임위 문의로 규제 여부를 확인한 뒤 붙인다(SPEC '유료 결제 전 게임위 문의').

## 배제한 대안

- 골드·햇살 현금 판매를 바로: 규제 확인 전이라 출시 때 막힐 위험(사용자가 배제).
- 판돈 구조부터 바꾸기(사람끼리 골드를 안 주고받게): 규칙 변경이라 따로 정할 일.

## 결과·확인

- 현금 묶음 버튼은 눌리지 않는다(테스트). 서버는 무지개 조각 현금 상품을 모른다 — 결제를 붙일 때 서버 검증(영수증)과 함께 추가한다.
- 옛 상품 id(hearts5·coins1000)는 원장 참조에 남아 있어 유지했다.
