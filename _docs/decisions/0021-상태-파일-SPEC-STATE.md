# ADR-0021: 목표는 SPEC.md, 지금 상태는 STATE.md로 매 세션 자동으로 읽힌다

상태: 확정 (2026-11-23, 사용자 결정)

## 문제

- 매 세션 자동으로 읽히는 것은 CLAUDE.md와 개인 메모리 목록뿐이었다(CLAUDE.md에 `@` 불러오기가 없었다).
- "지금 상태"를 담던 `SUVIS_ADMIN_MULTIAGENT_PROGRESS.md`는 641줄로 쌓여 있어 자동으로 읽히지 않았다. 11-23 "토요일에 하던 거 이어서" 요청에서 git 기록·worktree·워크로그를 직접 뒤져서야 머지 안 된 정산 커밋을 찾았다.
- 상태 갱신은 CLAUDE.md 지침에만 기대고 있어 빠뜨려도 막는 장치가 없었다.

## 결정

- 세 파일로 나눈다(사용자가 보여 준 "상태 파일은 에이전트가 알아서 관리" 구성을 따름).
  - `_docs/SPEC.md`: 앱별 목표·완료 기준. CLAUDE.md `@`로 매 세션 로드. 목표가 바뀔 때만 고친다.
  - `_docs/STATE.md`: 지금 상태·사용자 대기. `@`로 매 세션 로드. 단계를 마칠 때마다 덮어쓴다(30줄 안팎).
  - 완료 이력은 기존 `WORK_LOG_<앱>.md`가 맡는다(자동 로드 안 함, 맨 위에 추가). 이름을 HISTORY로 바꾸지 않는다.
- **코드를 바꾼 PR은 STATE.md도 같은 PR에서 고쳐야 머지된다** — `codex_gate.py`의 `gh pr merge` 관문이 막는다. 문서만 바뀐 PR은 예외.
- `harness_drift.py`가 두 파일도 비교한다. 메인 폴더가 main보다 뒤처지면 옛 STATE가 로드되므로, 다르면 `origin/main` 판을 따르라고 알린다.
- PROGRESS.md는 긴 백로그·완료 색인으로 남긴다(지우지 않음).

## 배제한 대안

- **PROGRESS.md를 그대로 `@`로 불러오기**: 641줄이 매 세션 컨텍스트를 차지한다. 상태 요약 역할에는 너무 길다.
- **앱별 STATE 파일 여러 개**: `@`로 모두 불러오면 결국 합친 것과 같고, 파일만 늘어난다. 한 파일 안에 앱별 줄로 둔다.
- **워크로그를 HISTORY.md로 개명**: 과거 문서·스크립트의 인용이 많고 ADR-0020 직후라 얻는 게 없다.
- **SessionStart에서 메인 폴더를 자동으로 `git pull`**: 메인 폴더 파일을 덮어쓰는 일은 사용자에게 먼저 묻기로 한 규칙(ADR-0009)과 충돌한다. 드리프트 알림으로 대신한다.
- **커밋마다 STATE 검사**: 한 PR 안의 중간 커밋까지 막아 번거롭다. 단계의 끝인 머지에서 한 번 본다.

## 결과·확인

- 새 세션(`claude -p`, 읽기 도구 차단)이 STATE.md의 갱신 날짜와 SPEC.md의 gildle 완료 기준을 답함 — 자동 로드 확인.
- `test_codex_gate.py`: STATE 없이 코드 PR 머지 거부 → STATE 추가 후 통과, 문서만 PR은 통과. STATE를 지운 PR·코드를 .md로 이름만 바꾼 PR도 거부, `_docs` 밖 .md만 바꾼 PR은 통과·한글 .md 경로도 문서로 판정·STATE 권한만 바꾼 PR 거부·이 브랜치에서 고친 STATE는 드리프트로 안 알림·`_docs` 아래 비문서 변경도 STATE 요구·main과 브랜치가 둘 다 고친 STATE는 알림·STATE를 지우거나 옮기는 문서 PR도 거부·STATE 경로를 디렉터리로 바꾼 PR도 거부·SPEC 삭제와 STATE 심볼릭 링크도 거부·빈(공백뿐) STATE·SPEC 거부·드리프트도 알림·비UTF-8 파일명에도 관문 동작·main 판을 복사한 STATE 거부·심볼릭 링크 STATE는 드리프트로 알림·UTF-8이 아닌 STATE는 예외 없이 거부·공통 조상이 없어도 드리프트 감지·드리프트도 UTF-8만 인정·공백·줄바꿈만 바꾼 STATE 거부·SPEC·STATE는 Codex 승인 범위에 포함·드리프트 목록에서 상태 파일을 맨 앞에·`_docs` 아래 비마크다운도 리뷰 범위·드리프트 목록에서 CLAUDE.md도 맨 앞·리뷰 입력에서 두 diff 경계 유지·잘못된 UTF-8이 있어도 리뷰 동작·NUL만 든 STATE 거부·옛 CLAUDE.md면 상태 파일도 읽게 안내·실행 중인 관문이 main보다 옛 판이면 머지 거부·리뷰 입력이 올바른 패치·관문을 고치는 PR은 그 PR 판으로 판정 허용(Codex 지적 37건, 각각 수정 전 실패 확인). 하네스 테스트 89개 통과.
