# ADR-0030: 쿠모니지는 비공개 저장소 suvisdev/kumoniji로 옮긴다

상태: 확정 (2026-11-28 사용자 결정) — 새 저장소 CD 첫 배포 확인과 공개 저장소 `kumoniji/` 삭제는 남음

## 문제

- 쿠모니지는 수익화할 앱(SPEC)인데 코드(서버 규칙·화폐·계정)가 공개 모노레포 `suvisdev.cloud`의 `kumoniji/`에 있었다.
- 사용자: 비공개 저장소 `suvisdev/kumoniji`로 옮긴 뒤 이 저장소에서 지운다(11-28).

## 결정

- `git subtree split --prefix=kumoniji`로 `kumoniji/`의 커밋 기록을 그대로 떼어 새 저장소 main에 올린다(덮어쓰기 없이 빨리감기로 따라잡는다). 노트북 클론은 `~/projects/kumoniji`.
- CI/CD는 새 저장소 루트의 `.github/workflows/ci.yml`(이름 kumoniji-ci)·`deploy.yml`(kumoniji-deploy)로 옮긴다. 개인 계정이라 러너를 저장소끼리 나눠 쓸 수 없어 노트북에 전용 러너 `~/actions-runner-kumoniji`(user 서비스 `actions-runner-kumoniji`, 라벨 prod, 같은 OS 계정)를 따로 둔다.
  CD가 읽는 `.env`는 러너 `.env`의 `KUMONIJI_DATA_ROOT`(= `~/projects/kumoniji`) 쪽 `.env`. 손 배포도 `~/projects/kumoniji`에서 `./deploy.sh`.
- 판 해시에서 `.github/`를 뺀다 — CI 설정만 바꾼 머지로 파드가 재시작돼 메모리의 대국이 사라지지 않게.
- 두 저장소의 CD가 같은 Deployment를 서로 덮지 않게, **공개 저장소의 `kumoniji-deploy.yml`을 먼저 지운 뒤** 새 저장소 CD를 켠다. 공개 저장소의 kumoniji-ci는 폴더를 지울 때 함께 지운다(그때까지 `codex_gate.py`가 그 검사를 요구한다).
- 지난 커밋 기록은 공개 저장소에 그대로 남는다(역사를 다시 쓰지 않는다).

## 배제한 대안

- 공개 저장소를 통째로 비공개로 돌리기: 포트폴리오로 공개하는 다른 앱(메인·mova·길들)까지 가려진다.
- 공개 저장소 역사 재작성(filter-repo로 `kumoniji/` 제거): 강제 푸시·열린 브랜치 전부 재작성이 필요하고, 이미 받아 간 사본은 지울 수 없다.
- 러너 하나를 두 저장소가 함께 쓰기: 개인 계정 저장소는 러너를 공유할 수 없다(조직 계정에서만 가능).

## 결과·확인

- 새 저장소 트리 = 공개 저장소 `origin/main:kumoniji` 트리(파일 단위 비교 일치, 11-28 #350 포함).
- 전용 러너 온라인(`teagy-kumoniji`, self-hosted·Linux·X64·prod).
