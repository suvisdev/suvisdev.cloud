# ADR-0013: 아침 메일에 기사별 풀이·분석을 노트북 7.8B로 붙인다

상태: 확정 (2026-11-16, 사용자 결정)

## 문제

- 메일은 제목·출처·2~3문장 요약뿐이라 사용자가 읽어도 무슨 뜻인지 알기 어렵다. 사용자는 기사마다 쉬운 설명과 이점·단점 분석을 원한다.
- RSS로 받은 글은 본문이 비어 있고 요약만 300자 안팎이다. 이것만으로 분석하면 거의 모델 추측이 된다.

## 결정

- 기사마다 "쉽게 말하면 · 왜 중요한가 · 이점 · 단점·한계 · 용어"를 넣고, 맨 위에 "오늘의 흐름" 3줄을 둔다.
- 풀이·분석과 흐름은 요약·분류와 같은 노트북 올라마 EXAONE 3.5 7.8B가 쓴다(사용자 선택).
- 메일에 들어갈 글만 원문 페이지를 받아 본문 3,000자까지 모델에 준다. 막는 곳(news.hada.io 403 등)은 우회하지 않고, 요약만 보고 쓴 풀이에 그렇게 표시한다.
- 용어 뜻은 모델이 쓰지 않고 기존 검수 사전(`glossary.json`)에서 찾는다(11-06 결정 유지).
- 메일 끝에 "모델이 쓴 것이라 틀릴 수 있다"고 밝힌다. 풀이 모델이 멈추면 남은 풀이를 건너뛰고 메일은 보낸다.

## 배제한 대안

- Gemini 무료 등급: 품질은 더 낫다고 보지만 사용자가 로컬 7.8B를 골랐다.
- 용어 사전만 붙이기: 틀릴 일은 없지만 "그래서 무슨 뜻인지"와 이점·단점이 없다.
- 수집 때 모든 글의 본문 받기: 하루 수백 건을 받아야 하고, 메일에 들어가는 건 10건뿐이다.

## 결과·확인

- 실제 기사 5건 시험: 글당 약 8초(5건 38.6초), 10건이면 약 1분 20초로 메일 잠금(15분) 안이다. 상세는 `WORK_LOG_MAINPAGE.md` 11-16.
- 틀린 풀이는 코드 규칙이 아니라 학습 데이터로 고친다(CLAUDE.md §5).
