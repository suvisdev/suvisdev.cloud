# ADR-0023: 쿠모니지 멀티는 서버 메모리·파드 1개·사람 4명으로 시작한다

상태: 확정 (2026-11-24, 계획 C `kumoniji/_docs/plans/2026-11-21-C-multiplayer.md`의 제약을 코드로 옮김)

## 문제

- 멀티는 판 상태, 대기열, 친구방, 소켓 연결을 어딘가에 둬야 한다. 운영은 노트북 한 대다(ADR-0008, 무료·단순).

## 결정

- **저장은 서버 메모리만**(`kumoniji/multi/lobby.py`의 `Lobby`). DB·Redis에 판을 쓰지 않는다. 배포하거나 파드가 재시작되면 진행 중인 판은 사라진다.
- **파드는 1개**(replicas 1). 잠금이 없고, 모든 처리가 한 이벤트 루프에서 돈다.
- **사람 4명만.** 빈자리를 봇으로 채우지 않는다. 끊긴 사람의 차례는 20초 타이머가 패스한다.
- 자동 매칭은 IP·기기가 겹치는 사람을 같은 판에 넣지 않는다(한 사람이 여러 창으로 들어오는 것 방지). 기기 구분은 앱이 보내는 머리글이라 클라이언트가 빼거나 바꿀 수 있다 — 기준은 IP이고 기기는 보조다(서버가 기기를 증명할 방법이 없음). **친구방은 IP 제한이 없다**(같은 집 친구). 대신 방 코드 대입을 막으려고 잘못된 코드는 계정당 분당 10회까지만 받는다.
- 인증은 HTTP와 같은 검사(`session_problem`)를 소켓에도 쓰고, 60초마다 세션을 다시 확인한다.

## 배제한 대안

- Redis에 판 저장 + 파드 여러 개: 노트북 한 대에서는 얻는 것이 없다. 판 하나는 몇 분이면 끝난다.
- 빈자리 봇 채우기: 매칭이 빨라지지만, 사람 판과 봇 판의 점수 의미가 섞인다. 동접이 생긴 뒤에 다시 본다.

## 결과·확인

- 서버 테스트: 소켓 4개로 자동 매칭부터 한 판 끝까지, 타이머 자동 패스 전송, 인증·Origin·크기·속도·유휴·로그아웃 종료(`tests/accounts/test_ws.py`).
- 다시 볼 때: 동접이 파드 1개로 모자라거나, 배포로 판이 끊기는 불만이 생길 때.
