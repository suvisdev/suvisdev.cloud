# ADR-0012: 공개 LLM 엔드포인트의 요청 제한은 shared 의존성 하나가 Redis에 센다

상태: 확정 (2026-11-13, 사용자 결정)

## 문제

- 홈 채팅·mova 채팅의 IP별 요청 제한이 앱마다 복사본으로 있었고, 프로세스 메모리라 main 머지마다 CD 재배포로 0이 됐다.
- "API 게이트웨이가 필요한가"에서 출발해 요청 제한을 어디에 둘지 정해야 했다.

## 결정

- `shared/security/rate_limit.py` 하나를 두고 Redis ZSET 슬라이딩 로그(Lua 원자 처리)로 최근 60초 IP당 20회를 센다. 엔드포인트마다 따로 센다.
- Redis가 응답하지 않으면 그 엔드포인트만 503으로 막는다.

## 배제한 대안

- 현행 유지 + 복사본 합치기: 가장 싸지만 재배포 초기화가 남는다.
- Traefik RateLimit 미들웨어: 앱 앞에서 막지만 토큰 버킷으로 의미가 바뀌고, 기본값은 cloudflared 뒤라 전원이 한 버킷이 된다(실험 확인). 로컬·pytest로 시험할 수 없다.
- Cloudflare 무료 규칙: 10초 단위만 돼 정책을 옮길 수 없고 대시보드 설정이라 시험하지 못했다. 실제 폭주가 오면 바깥 방어로 더한다.
- Redis 장애 때 메모리 폴백: 카운터가 둘로 갈린다. 비용 방어가 목적이라 막는 쪽을 택했다.

## 결과·확인

- 실험·검증은 `WORK_LOG_MAINPAGE.md` 11-13. 게이트웨이는 두지 않는다(서비스 2개, Traefik Ingress로 충분).
