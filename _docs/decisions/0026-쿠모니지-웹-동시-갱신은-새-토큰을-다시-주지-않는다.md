# ADR-0026: 쿠모니지 웹 동시 갱신에는 새 토큰을 다시 주지 않는다

상태: 확정 (2026-11-26 사용자 결정 "3번", 적용은 화폐 앱 PR)

## 문제

- 웹은 리프레시 토큰과 재시도 키를 둘 다 쿠키에 둔다. 같은 브라우저의 탭 여러 개가 동시에 갱신하면, 방금(30초 안·같은 IP) 회전된 토큰으로 온 요청에도 같은 새 토큰을 다시 줬다.
- 그러면 쿠키 두 개를 함께 훔친 사람이 주인과 같은 공인 IP에서 회전마다 30초 안에 따라붙으면 정상 동시 갱신으로 처리돼, 하루 한도(192회) 아래로 세션을 며칠씩 쓸 수 있었다(Codex 지적, 심각도 높음).
- HttpOnly 쿠키를 훔칠 정도면 대개 그 PC의 악성 프로그램이라, "같은 IP" 조건은 거의 걸러 주지 못한다.

## 결정

- **웹의 동시 갱신에는 409(`rotated`)만 주고 새 토큰을 다시 주지 않는다.** 탭은 쿠키를 함께 쓰므로, 먼저 회전한 탭의 응답이 심은 새 쿠키로 다시 보내면 된다(앱은 이미 409에 1초 기다렸다 다시 보낸다).
- 웹인지는 요청 헤더가 아니라 **재시도 키로 판단한다.** 웹 키는 서버가 세션에서 만든 값(`retry_key(sid)`)이라, 훔친 쿠키를 앱 경로(헤더·본문)로 보내도 웹으로 걸린다.
- 앱(휴대폰)은 그대로 다시 준다. 앱의 재시도 키는 메모리에만 있어 저장소를 훔쳐도 같이 새지 않는다.

## 배제한 대안

- 1번: 알고 둔다 — 쿠키 두 개와 같은 IP라는 조건이 실제로는 약하다.
- 2번: 하루 한도를 낮춘다 — 탭을 여러 개 띄워 두는 정상 사용자도 함께 로그아웃된다.

## 결과·확인

- 웹에서 갱신 응답을 잃은 탭은 30초가 지나야 다시 받기로 복구된다(그 사이 한 번 실패하거나 다시 로그인할 수 있다).
- 서버 테스트: 같은 IP에서 쿠키를 통째로 훔친 쪽이 30초 안에 와도 409·새 토큰 없음, 앱인 척해도 같음(수정을 빼면 실패).
