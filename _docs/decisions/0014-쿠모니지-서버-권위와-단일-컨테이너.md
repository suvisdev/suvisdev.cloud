# ADR-0014: 쿠모니지는 서버가 판정하고, 웹 앱은 서버 컨테이너가 함께 낸다

상태: 확정 (2026-11-18, 사용자 승인한 1단계 계획)

## 문제

- 쿠모니지(4인 타일 게임)를 웹 → 안드로이드 → 아이폰 순으로 낸다. 1단계는 봇 3명과 혼자 치기, 2단계는 4인 멀티, 이후 재화·결제가 붙는다.
- 규칙은 바탕화면 기획 폴더의 `rules.py` + 손으로 계산한 `cases.json`(88개)으로 이미 검증돼 있다. 규칙을 어디서 판정할지, 웹 앱을 어떻게 띄울지 정해야 한다.

## 결정

- **판정은 서버(FastAPI)가 한다.** 검증된 `rules.py`를 그대로 엔진으로 옮기고, 한 수씩 진행하는 `Game`을 얹는다. 앱(Flutter)은 서버가 준 상태만 그린다. 남의 손패는 장수만 준다.
- `Game`이 하네스 기준 구현(`rules.simulate`)과 같은 결과를 내는지 사례 전부 + 봇 500판으로 대조하는 테스트를 둔다.
- 앱은 Flutter 하나로 웹·안드로이드·아이폰을 만든다. 웹 빌드 결과는 서버 컨테이너가 정적 파일로 같이 낸다(컨테이너·Deployment·도메인 하나, CORS 없음).
- 1단계 판은 메모리에만 둔다(최대 2,000판, 재시작 때 사라짐). 그래서 replicas는 1이다. 계정 단계에서 DB로 옮긴다.
- 웹 빌드는 노트북에서 한다. 공개 Flutter 도커 이미지에 쓰는 버전(3.47)이 없어서다.
- Codex가 준 패 SVG는 flutter_svg가 못 그리는 구조(`<symbol>`/`<use>`, 중첩 `<svg>`, filter)가 있어 `app/tool/flatten_svg.py`로 펴서 넣는다.

## 배제한 대안

- 앱 안에서 판정: 1단계는 서버 없이 되지만 Dart로 규칙을 한 번 더 짜야 하고, 멀티 때 결국 서버로 다시 옮겨야 한다. 두 구현이 갈라지면 어느 쪽이 맞는지 하네스로 가릴 수 없다.
- 웹 정적 파일을 따로 호스팅(nginx·Pages): 컨테이너·라우팅·CORS가 하나씩 늘어난다.
- 1단계부터 DB: 계정이 없어 판을 오래 둘 이유가 없다.

## 결과·확인

- 서버 테스트 117개(규칙 사례 88 + 전수 분류 + Game 대조 + API), 앱 테스트 4개 통과. 컨테이너 로컬 실행에서 웹·API·패 그림 200 확인. 상세는 `WORK_LOG_MAINPAGE.md` 11-18.
