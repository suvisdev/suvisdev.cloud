# ADR-0024: 쿠모니지 화폐는 1점당 판돈 50, 자동 매칭에서만, 큰 처음 지급 없이

상태: 확정 (2026-11-24 사용자 결정, 계획 D `kumoniji/_docs/plans/2026-11-24-D-currency.md`)

## 문제

- 기획(PRODUCT.md §4)에 판돈·하트·유료 재화(보석) 구조는 있었지만 판돈의 가치·처음 지급·싱글/친구방 적용·미션은 비어 있었다(결정 E3·E4·M5).

## 결정

- **1점 = 판돈 50.** 정산 점수(상한 없음)에 50을 곱해 주고받는다. 단 잔고 아래로는 내지 않는다(빚 없음) — 받는 사람은 실제로 걷힌 만큼 나눠 받는다.
- **판돈은 자동 매칭에서만.** 싱글(봇)은 판돈을 새로 찍어 내는 통로가 되고, 친구방은 짜고 져서 몰아주는 통로가 되므로 둘 다 점수만.
- **처음 큰 지급·파산 구제 없음.** 사용자: "처음에 10000을 주고 3000원 주는 경우면 도박사이트 같다." 판돈은 출석(하루 200, 7일째 500)·일일 미션(10개 중 5개 완료, 하나 100)으로 가볍게, 나머지는 보석 구매·광고.
- **결제는 붙이지 않는다.** 보석은 잔고·원장·사용처만. 결제는 게임위 문의 뒤(SPEC).
- 모든 증감은 원장(`ledger`)에 남기고 `(계정, 종류, 참조)` 고유 제약으로 같은 판·보상이 두 번 들어가지 않게 한다.

## 배제한 대안

- 판마다 100씩 걸고 점수대로 나누기(손실 상한 100): 덜 출렁이지만 사용자가 1점당 방식을 골랐다.
- 1점당 100: 보상(하루 약 2,000)에 비해 진 사람 손실(평균 약 1,000~3,000)이 커서 무료로 하루 한 판 수준 → 50으로 낮춤(사용자).
- 처음 10,000 지급 + 파산 구제: 위 사용자 발언으로 버림.

## 결과·확인

- 숫자는 `kumoniji/server/kumoniji/wallet/money.py` 한 곳(구현 때). 기본값(입장 최소 500, 상점 값, 7일째 보석 10, 5개 보너스 300, 누적 점수 기준 30)은 계획 D 표에 이유와 함께.
- 다시 볼 때: 판돈이 한쪽에 몰리거나(잔고 분포), 무료 이용자가 하루에 칠 수 있는 판 수가 너무 적다는 불만이 있을 때.
