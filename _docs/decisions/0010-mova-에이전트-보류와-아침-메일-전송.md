# ADR-0010: mova 에이전트는 끈 채로 두고, 아침 메일은 Gmail SMTP로 보낸다

상태: 확정 (2026-11-09, 사용자 결정)

## 문제

- `MOVA_CHAT_AGENT`는 10-02 집컴 CPU 지연으로 꺼진 뒤 노트북 GPU로 옮긴 뒤에도 0이었다. 켜면 멀티턴 하네스가 17/20에서 19/20으로 오르고 취향 요약이 돌아온다. 하지만 v9(2GB)는 7.8B·lora와 함께 8GB VRAM에 들어가지 않고, 뉴스 요약과 아침 메일 분류가 7.8B를 쓴다.
- 아침 메일에는 발송 수단이 필요한데, 기존 경로인 n8n 웹훅이 운영 `.env`에서 비어 있다.

## 결정

- `MOVA_CHAT_AGENT=0`을 유지한다.
- 아침 메일은 표준 라이브러리 `smtplib`으로 Gmail SMTP에 직접 보낸다. 값은 환경 변수로 받고, 없으면 메일 기능은 꺼진다.

## 배제한 대안

- 에이전트 켜기: 얻는 것이 시험 2건과 취향 요약이고, 뉴스 작업 중 모델이 번갈아 올라가는 비용을 재지 못했다.
- n8n 경유: 무료지만 메일 하나를 위해 워크플로 서버를 더 운영해야 한다. Arda의 n8n은 쓰지 않는다.
- 유료 메일 API: ADR-0001(무료 기반)에 어긋난다.

## 결과·확인

- 측정은 `WORK_LOG_MOVA.md` 11-09 (2). 7.8B 작업을 2.4B로 옮기거나 VRAM이 늘어나면 에이전트를 다시 잰다.
