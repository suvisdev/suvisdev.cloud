# ADR-0029: 쿠모니지도 CI가 통과하면 자동 배포한다

상태: 개정됨 → ADR-0030 (워크플로·러너·.env 위치가 새 저장소로 옮겨짐)

## 문제

- 백엔드는 main 머지 → backend-ci 통과 → 노트북 러너가 자동 배포(2026-10-01)인데, 쿠모니지는 머지 뒤 사용자가 `./kumoniji/deploy.sh`를 직접 돌렸다.
  하네스 자동 모드가 배포 명령을 막아 머지된 PR이 며칠씩 '운영 배포 대기'로 쌓였고(11-28 #334·#335·#337·#338), 메인 폴더를 `git pull`하지 않아 옛 코드가 나간 적도 있다(11-27).
- 사용자: "배포 금지를 한 적이 없다", "CI/CD가 문제없이 돌아가면 자동으로 배포돼도 된다".

## 결정

- `kumoniji-deploy` 워크플로: main push로 돈 kumoniji-ci가 성공하면 노트북 셀프호스티드 러너(라벨 prod)가 CI가 통과한 커밋을 체크아웃해 `kumoniji/deploy.sh`를 실행하고 외부 주소 응답을 확인한다.
  `.env`는 러너 `.env`의 `SUVISDEV_DATA_ROOT` 쪽 `kumoniji/.env`. 동시 실행 묶음은 커밋마다 따로 — 한 묶음을 같이 쓰면 대기 중인 실행이 서로 취소된다(백엔드 묶음, 옛 커밋 CI 재실행). 러너가 하나라 잡은 어차피 하나씩 돈다.
- `deploy.sh`는 파일 잠금으로 손 배포와 CD 배포를 한 번에 하나만 돌리고, CD일 때(`KUMONIJI_CD=1`) 잠금 안에서 판단한다: 체크아웃한 커밋의 `kumoniji/`가 지금 main과 다르면 건너뛴다 — 옛 커밋 CI를 다시 돌려도 운영이 되돌아가지 않는다. 지금 도는 판과 같은 `kumoniji/` 트리여도 건너뛴다(`deploy.sh`가 롤아웃 성공 뒤 deploy 주석 `kumoniji/tree`에 적음, 커밋 안 된 수정이 있으면 dirty) — 재시작하면 메모리의 대국이 사라진다.
- 쿠모니지 DB 마이그레이션(`accounts/migrations/*.sql`)은 서버가 시작할 때 자동 적용되므로, 그 파일이 바뀐 PR은 `codex_gate.py`가 머지를 막고 사용자 확인(덤프)을 받는다 — 백엔드 alembic과 같은 규칙. 웹에서 머지해 이 관문을 안 거쳐도, CD는 운영 DB `schema_version`에 없는 마이그레이션이 든 판을 내보내지 않고 실패로 알린다 — 사용자가 덤프 뒤 손으로 `./kumoniji/deploy.sh`. (CD가 서버를 내리고 자동 덤프하는 안은 실패·취소 때 서버가 내려간 채 남는 경우가 계속 나와 버렸다.)

## 배제한 대안

- 계속 수동 배포: 머지와 운영이 어긋난 채로 쌓이고, 옛 코드를 내보내는 사고가 이미 있었다.
- 배포마다 사용자 승인(GitHub environment 보호): 사용자 결정이 '문제없으면 자동'이고, 위험한 경우(마이그레이션·새 비밀값)는 머지 전 관문에서 이미 걸러진다.
